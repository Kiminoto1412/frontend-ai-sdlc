## What this is

Farmart — a Next.js (App Router) storefront for an online grocery store. See `PLAN.md` for the full feature roadmap/business goals and `DESIGN.md` for the visual design system (colors, typography, component conventions, do's/don'ts). **Read `DESIGN.md` before writing any UI** — it's the authority on styling, not this file.

## Node version

Use Node from `.nvmrc` (currently `22`): `nvm use`. Storybook 10 requires Node 20.19+/22.12+, which is higher than Next.js's own minimum (18.18+), so the project pins the higher version to keep one Node version working for everything.

## Commands

```bash
npm run dev              # Next.js dev server (Turbopack) — http://localhost:3000
npm run build             # production build
npm run start             # serve the production build
npm run lint               # ESLint (flat config, includes eslint-plugin-storybook)
npx tsc --noEmit           # typecheck (no dedicated package.json script)

npm run storybook          # Storybook dev server — http://localhost:6006
npm run build-storybook    # static Storybook build → storybook-static/

npx vitest --project storybook run                          # run all component (play-function) tests
npx vitest --project storybook run src/components/Foo.stories.tsx   # run a single story file's tests

npx @google/design.md lint DESIGN.md   # validate DESIGN.md's YAML frontmatter/tokens (0 errors, 0 warnings expected)
```

Storybook and `npm run dev` are **independent servers on different ports** — you don't need one running to use the other.

## Architecture

- **App Router only** (`src/app/`) — no `pages/` directory. Routes:
  - `/` — homepage (`src/app/page.tsx`), assembled from section components in `src/components/`
  - `/design` (`src/app/design/page.tsx`) — a live style-guide page that renders `DESIGN.md`'s conventions using the *actual* components (not a static copy). When a component or pattern is added/changed, update `DESIGN.md` and this page together.
  - `/product/[id]` (`src/app/product/[id]/page.tsx`) — dynamic product detail page; `params` is a `Promise` (Next.js 16 async params API — `await params` before use). Uses `generateStaticParams` + mock lookup from `src/data/products.ts`; unknown ids call `notFound()`.
  - `/overview` (`src/app/overview/page.tsx`) — a `@xyflow/react` (React Flow) diagram of every route above and the real links between them, generated by reading the codebase (not an idealized flow). Re-check this against the actual routes/links whenever a page or navigation link changes, the same way `/design` is kept in sync with `DESIGN.md`.

- **`src/components/`** — flat directory, no subfolders or barrel file. Every component is colocated with its own `*.stories.tsx` Storybook file (same name, same directory). There is no separate `__tests__` folder — component tests live as `play` functions inside the story files and run against real Chromium via `@storybook/addon-vitest` + Playwright (not jsdom). Beyond `ProductCard`, the reusable primitives are `Dialog` (native `<dialog>`-based modal), `Rating`, `QuantitySelector`, `Breadcrumbs`, and `ProductGallery` — check `DESIGN.md` §4 and reuse these before building a new equivalent.

- **No backend/API** — all data is inline mock data: page-/section-specific arrays live directly inside the component that uses them (e.g. `BestSeller.tsx`, `TopSaver.tsx`), while `src/data/products.ts` holds the shared mock dataset for product detail pages (`ProductDetail` type, `getProductById`).

- **Styling: Tailwind CSS v4, CSS-first config** — there is no `tailwind.config.js`. Theme tokens (brand colors, etc.) are defined as CSS variables in `src/app/globals.css` under `@theme inline` (e.g. `--brand`, `--brand-dark`, `--brand-soft`). Path alias `@/*` → `./src/*` (see `tsconfig.json`).

- **`.storybook/preview.tsx`** imports the real `src/app/globals.css` so stories render with actual Tailwind output — no separate story-only styling setup.
